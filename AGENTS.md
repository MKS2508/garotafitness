If a decoder is not working properly find out how it should work by reverse engineering the DLL, not assuming it would work in a specific way. The official installer has the tools in there.

Name a new atom from the PE banner. Read endian and width from the load instruction.

Write the oracle before the first edit: input offset, compressed size, output size, and one IEEE CRC or installed MD5. Done when that length and that checksum both match. A matching length with a different checksum is unfinished until the ident fields and the leftover input agree. A test that skips the checksum is unfinished.

Where official C or C++ exists, a native HOST_DEBUG build of that same guest prints the same length and checksum on the same buffer.

Prove one corpus's installed MD5 manifest before starting the next.
