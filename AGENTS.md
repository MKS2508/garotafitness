If a decoder is not working properly find out how it should work by reverse engineering the DLL, not assuming it would work in a specific way. The official installer has the tools in there.

Name a new atom from the volume method string and the PE banner. Use the decode entry the package already names. Read endian and width from the load instruction.

Write the oracle before the first edit: input offset, compressed size, output size, and one IEEE CRC or installed MD5. Done when that length and that checksum both match. A matching length with a different checksum is unfinished: check ident fields and leftover input before treating the length as real. A test that skips the checksum is unfinished.

Where official C or C++ exists, a native HOST_DEBUG build of that same guest prints the same length and checksum on the same buffer.

One corpus per change. The pass is that corpus's installed MD5 manifest, with the file counts written down. A CPU profile written for that run is non-empty. On a live run, read one pid: RSS, heap inuse, and cumulative alloc_space. A freeze is a stretch of ticks with no progress.
